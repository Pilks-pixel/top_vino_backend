# Sanitized sandbox incidents

No live incidents are recorded yet. Do not confuse an untested sandbox with a healthy one.

A user-impacting incident means unexpected unavailability remaining after the cold-start retry, unexpected loss/corruption, security exposure or quota suspension preventing intended use. A failed candidate leaving the prior instance healthy and testers unaffected is only an operational event.

Copy this template per incident. No names/emails, credentials, endpoint values, raw logs, request bodies/queries, personal data or exploit details. Broad cause categories and correlation evidence may be kept privately.

| --- | --- |
| Date (Asia/Bangkok) / duration | Pending |
| User impact / data scope | Pending |
| Cause category | Build / migration / readiness / dependency / quota / security / other |
| Recovery / whether fixtures were reseeded | Pending |
| Owner recovery minutes | Pending |
| Notice due / sent | 72 hours planned; next business day emergency loss |
| Follow-up / reviewed issue | Pending |
| Graduation review | Rolling 30-day count, monthly recovery minutes, other trigger |

Two user-impacting incidents within 30 days, over two recovery hours in a month, or any quota suspension forces a durability decision. See [operations](../sandbox-operations.md).
